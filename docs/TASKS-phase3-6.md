# TASKS — Phase 3.6, the quiet week

This is the record of Phase 3.6, closed 2026-09-03. The live list is `TASKS.md`. Rows 2 and 3 were still in review at the close and are carried there as 0.1 and 0.2.

**Phase goal:** the tree becomes boring. Phase 3.5 shipped in one day — rewind, marks, cancellation, counsel, web — and none of it has been *lived in* yet. This phase is a week of daily use with no planned rows: friction found in the drives folds in here as it always has, gets fixed, and the list stays short. Voice (Phase 4) starts when a week passes where nothing worth filing appears — the same rule every phase boundary has held to: real usage is the input to the next phase's design, and a feature shipped this afternoon is not yet real usage.

Bogdan assigns each task; the other reviews it. Statuses are `todo` → `in progress` → `in review` → `done`.

| 1 | herdr integration: the TUI reports its own lifecycle instead of being screen-scraped. herdr 0.8 gives each pane one status authority — Claude Code earns it through installed hooks; arc, owning its harness, earns it natively. When `HERDR_PANE_ID` is set, a fire-and-forget reporter (arc-core module, wired in the client) speaks newline-delimited JSON over the local socket (`HERDR_SOCKET_PATH`, else `~/.config/herdr/herdr.sock`): `pane.report_agent` with source `custom:arc`, agent `arc`, mapping Streaming → working, Disconnected → blocked, the idle prompt → idle — three states, the entire report vocabulary. `pane.report_metadata` carries the session name as title and running-job counts as tokens — presentation only; semantic state belongs to the interactive turn, never to background jobs. Reporting never blocks the UI, never surfaces its own failures, and is inert outside herdr; nothing touches the log — display only, no events, no proto change. Learned against the live server (0.8.0, protocol 19), none of it in the docs: the socket answers one request per connection then hangs up, so the pump connects per report; reports carry a `seq` the server remembers per source *across processes*, so seq is epoch-milliseconds, not a counter from zero; and a report outlives its process — quitting sends `pane.release_agent` (plus a metadata clear) or the pane wears arc's last state forever, so `run()` returns through a `shutdown` that flushes both with a 500ms cap. And the one the first real drive caught: `done` is not reportable — the server rejects the literal string, so a finished turn stuck at *working* and no notification fired; herdr derives done from a working→idle transition itself and clears it on pane focus, which means done-until-you-look and cancel semantics belong to herdr, and arc's own logic for them was deleted, not fixed. Verified in a scratch pane: idle against the live daemon, blocked against a dead port, authority released on `:q`, working→idle rendering as done replayed byte-for-byte at the socket. Protocol: https://herdr.dev/docs/socket-api/ | claude | done |

| 13 | the handback carries the job's footprint, counted by the daemon. The doctrine says a handback is the job's claim "unless you checked", and the concierge had nothing to check with — so it repeated invented commit names and a job's "verified visually" without a way to doubt either. Verification by browsing (a read tool, arbitrary commands) is the wrong shape: it puts files in the long-lived cached context, tempts a low-thinking model into the executor's job, and would not have caught what went wrong here. Evidence is the right shape: when a turn ends, arcd appends what changed in the project while it ran — new commits by change id and message, then the files as `diff --stat` counts them — measured from a mark the daemon takes as the turn starts (the working-copy commit id after a snapshot; `jj diff --from <that> --to @` still resolves after the snapshot rewrites it). jj first, git as the fallback, no repo means no footprint; the commands run through the project's `command_prefix` with the same scrubbed environment as the bash tool (`arc_core::footprint`, one helper shared with bash). The engine places the block after the summary and before the continue_job line, so a cut report never cuts the count. Every clean turn carries one — the brief's, a concierge steer's, the user's own — and stops do not. Doctrine: compare the report against the footprint and say where they differ; a claim with nothing in the footprint behind it is a claim. Judgment stays with the expert and with Bogdan at the real screen; a fixed test runner is the one browsing-shaped tool worth revisiting if a job ever lies about tests passing. | claude | done |
