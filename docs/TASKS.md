# TASKS — Phase 3.7, the direct door

This is the live list. `TASKS-phase1.md` through `TASKS-phase3-6.md` are historical records. `DESIGN.md` defines the phase under sections 1, 4.1, 4.4, 5.4, 7, and 11, all amended 2026-09-03.

**Phase goal:** the executor becomes the session the user develops in. The quiet week's own numbers decided it: seven of thirteen rows repaired what the concierge lost, cut, or invented between Bogdan and a job, and the doctrine constant grew to thirteen lines patching a relay that cannot read the code. The concierge keeps the conversation, memory, grounding, and away-from-keyboard dispatch, which is the shape voice needs. Development moves to the bound session, which needs to feel like the harness it replaces: messages land mid-turn, tool output is on screen, a long day compacts instead of dying.

Order matters here. The runner (row 1) is the simplification the rest stands on; compaction (row 4) is the one nothing else waits for and the one a real session hits first; the door (row 6) is the cheapest and goes last.

**Exit criterion:** a week of development in `:code` sessions, the concierge used for talk and for dispatch from away, and compaction having fired on real work without a visible loss.

Bogdan assigns each task; the other reviews it. Statuses are `todo` → `in progress` → `in review` → `done`. Assignees are intentionally unset.
